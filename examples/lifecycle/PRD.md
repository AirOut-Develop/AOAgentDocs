# 제품 요구사항 — 제목을 작성한다

## 문제와 사용자
누가 어떤 상황에서 겪는 문제인지, 현재 증거를 적는다.

## 목표와 비목표
출시 범위와 보류 범위를 구분한다. 계획 플랫폼과 현재 지원 플랫폼을 혼동하지 않는다.

## 요구사항과 수용 기준

|---|---|---|---|---|
| REQ-EXAMPLE-01 | 실제 동작으로 교체 | 관찰 가능한 결과로 교체 | server | 실제 검증 명령/시나리오 |

## 제약과 위험
계정/접근권한, 개인정보, 성능, 접근성, 하위 호환, 오류/복구 기준.

## 결정과 변경
미결 결정·결정 주체·revision별 변경 영향. 실제 검토 없이 승인 기록을 만들지 않는다.
