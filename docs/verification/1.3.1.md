# AOAgentDocs 1.3.1 — 첫 사용자 Git 등록 회귀

## 발견과 처리

1.3.0은 ZIP 설치/검증은 통과했으나 실제 소비자 Git 등록에서 기존 PROJECT_ENV 템플릿의
CRLF가 확인됐다. `core.autocrlf=true`로 Git add하면 CRLF가 LF로 바뀌어 저장된 blob이
설치 manifest의 hash와 달라졌다. 1.3.0의 태그/ZIP은 수정하지 않고 1.3.1로 보완한다.

## 수정 범위

- 설치기가 `.aodocs/.gitattributes`에 두 줄을 기록한다.
  `.gitattributes -text` / `kit/** -text whitespace=cr-at-eol`.
- 속성 파일 자체의 CRLF 변환도 막는다. 기존 다른 내용/링크/비파일 충돌은 쓰기 전에 거부한다.
- 1.3.1 이상 validator가 속성 파일의 존재/정확한 내용을 검사한다.
- 기존 프로젝트 root 속성과 문서 내용은 변경하지 않는다.

## 검증

환경: Python 3.10.12, WSL Linux, Git에서 core.autocrlf=true를 실제 설정한 임시 소비자.
소스: `79db96780fb5660557b94373c17b4f7eedfaebf0`.
ZIP SHA-256: `cd8a8d5501b880428f5b178f7e2ed850458194c695d59a077d4ab9317dfccfa0`.

- 기존 동작에서 staged blob hash 불일치 테스트 실패를 재현한 뒤 수정했다.
- 전체 unittest 85개 통과. Python 문법/shell syntax/diff 검사 통과.
- 실제 Git init → autocrlf 설정 → ZIP/킷 설치 → add → commit → clone → installed CLI validate 통과.
- 첫 소비자 AOCortexAPI에서 1.3.1 ZIP으로 업데이트, 사용자 metadata 불변, 재실행 무변경.
- 소비자 `git diff --cached --check` 통과.
- 소비자 staged payload 45개 모두 Git blob SHA-256과 manifest SHA-256이 일치했다.

native Windows/macOS에서의 실행 자체는 미검증이다. 이번 검증은 Git 줄바꿈 변환을
실제로 켠 환경에서의 데이터 보존 증거이며 OS 전체 호환 판정은 아니다.
앱 로그인 문제는 별도 미해결 이슈로 유지한다.

## 이미 영향을 받은 checkout 복구

독립 리뷰에서 이미 CRLF로 checkout된 1.3.0의 upgrade 충돌을 추가 발견했다.
정확히 1.3.0→1.3.1 이상이며 LF/CRLF 변환 결과가 원래 hash와 일치할 때만 복구한다.
다른 내용 변경·다른 설치 버전은 계속 거부한다. 실제 공개 1.3.0 ZIP(고정 checksum)을
테스트 fixture로 보존하고 install/commit/autocrlf clone/upgrade/recommit/reclone/validate를 검증했다.
이 fixture는 tests 아래에 있으며 배포 payload에는 포함하지 않는다.

최종 테스트: installer 32 + validator 45 + distribution 8 = 85 passed.
독립 재검토에서 해당 upgrade 차단점 해소를 확인했다. LSP 진단은 미검증이다.
첫 소비자 커밋: AOCortexAPI `93a02c2cfd2cdde8f501c1ec7295b054bba002bb`, 원격 main 일치 확인.
