# AOAgentDocs 1.3.0 검증 기록

## 범위

Python 3.10.12 / WSL Linux에서 킷 설치·업그레이드·문서 검증·ZIP 재사용을 확인한다.
원본 개발과 소비자 프로젝트는 독립 Git 저장소이며 기존 Platform 서버 전용 포크는 변경하지 않는다.

## TDD와 독립 리뷰

- installer: missing module, 파일/디렉터리 충돌, portable path, 버전/downgrade,
  TARGET='.'의 빈 project_id, symlink ancestor 테스트가 구현 전 실패함을 확인했다.
- validator: missing module, 타입/승인/상태/coverage, metadata/kit symlink,
  관리 목록 누락, 계획 플랫폼의 완료, 이름 참조 링크 실패를 재현했다.
- distribution: missing packager, bool schema 실패를 확인한 뒤 구현했다.
- 독립 리뷰에서 source pin/설치 안내 경로/계획 플랫폼/관리 목록/링크 경계를 지적받고
  각 항목을 회귀 테스트 또는 실제 명령·문서 정합으로 수정했다.

## 첫 소비자 설치

AOCortexAPI `4975f46` 기준으로 추적 파일 345개의 hash를 기록했다.
ZIP을 별도 임시 위치에 풀고 그 안 CLI로 server+iOS profile을 설치했다.
dry-run에서 파일 생성 0건, apply 직후 기존 추적 파일 변경 0건, 재실행 변경 0건이었다.
소비자 문서 지도/registry는 별도로 추가했다. 기존 파일 중 README에는 명시적 탐색 링크만 추가했다.
향후 Android는 planned로 두었다.

실제 PRD/계획/미해결 로그인 ISS/검증을 등록했고 임시 복제의 중복 ID,
검증 근거 없는 완료, 관리 파일 변조를 각각 nonzero로 거부했다.
소비자 제품 로컬 테스트는 gateway 57 + 앱 도구 26 + bench 19 = 102개 통과했다.

## 구분해야 할 한계

- 문서 검사는 승인 진위/테스트 실행/제품 기능/보안 검증을 대신하지 않는다.
- Apple 로그인 실패는 여전히 미해결이며 이번 작업에서 실기/서버 배포를 하지 않았다.
- Android 네이티브는 계획이고 구현/검증 완료가 아니다.
- Windows PowerShell wrapper는 동일 Python packager에 위임하며 native Windows 실행은 미검증이다.
- macOS native 실행, mypy/pyright/shellcheck는 이번 환경에서 검증하지 않았다.
- full CommonMark parser가 아니므로 정의 없는 단축 참조는 검사 범위 밖이다.
- 동시 설치나 전원/I/O 중단 시 원자적 rollback은 지원하지 않는다. preflight 충돌은 쓰기 전에 거부한다.

  모두 exit 1로 거부. 소비자 제품 테스트 102개 재실행 통과.

  canonicalize하고 선택한 root/관리 경계의 symlink는 거부하는 것으로 범위를 정정했다.
- LSP 진단 도구가 없으므로 해당 진단은 미검증이며 독립 리뷰의 형식적 APPROVE를 주장하지 않는다.
  테스트·코드/명세 대조에서 남은 릴리스 차단점은 보고되지 않았다.
