# AOAgentDocs 1.3.0 — 제품 문서 생명주기

상태: 실행 기준. 사용자는 2026-09-05 원본 버전 개선과 AOCortexAPI 첫 사용자 검증을 요청했다.
1.3.0은 기존 WRK/ISS를 이동/삭제하지 않는 선택적 확장이다.

## 요구사항

- KIT-01: 기존 root 지침/PRD/이력/버전 marker를 덮어쓰지 않고 `.aodocs/kit`에 설치한다.
- KIT-02: Python 표준 라이브러리만 사용한다. 설치 기본은 dry-run, `--apply`만 변경한다.
  첫 설치 후 manifest hash와 다른 로컬 파일은 충돌로 중단한다. symlink/경로 탈출을 거부한다.
- KIT-03: `.aodocs/project.json`은 사용자 소유의 project_id/platforms/planned_platforms를,
  `.aodocs/documents.json`은 문서 metadata를 관리한다. 기존 사용자 파일은 보존한다.
  `.aodocs/manifest.json`은 kit_version과 관리 파일 SHA-256만 설치기가 갱신한다.
- KIT-04: 문서 registry 형식은 `{schema_version:1, documents:[...]}`다.
  record 필수는 id/kind/path/status/revision/owner/platforms다. id는 대문자 영숫자/하이픈,
  revision은 양의 정수다. path는 프로젝트 내부 기존 Markdown 파일이다.
  refs/evidence/requirements/covers는 선택적 ID 배열이다. 서로 다른 doc ID와 requirement ID는 중복 불가.
- KIT-05: kind별 상태: prd/design/adr=draft,in_review,approved,superseded,withdrawn;
  plan/work/issue=planned,in_progress,blocked,done,cancelled;
  verification=not_run,passed,failed,waived; release=not_deployed,canary,released,rolled_back.
  승인 문서는 approval={by,at,revision}을 가지며 revision이 일치해야 한다.
  passed 검증에는 command/environment/source_revision 문자열이 있어야 한다.
  waived에는 reason/owner/expires_at이 있어야 하며 passed로 취급하지 않는다.
- KIT-06: done work/plan/issue와 released release는 evidence로 passed verification을
  최소 1개 연결한다. 해당 작업 covers에 있는 요구사항은 그 evidence의 covers 합집합에 있어야 한다.
  requirements는 prd에서 정의하며 covers는 정의된 requirement를 참조한다.
  refs/evidence는 존재하는 doc ID를 참조한다. 미래 Android 요구사항을 완료로 표시하지 않는다.
- KIT-07: validate는 registry, 프로젝트 metadata, 관리 kit hash와 등록 문서 상대 링크를
  검사하고 위반 시 nonzero exit한다. 외부 URL/앵커/실제 테스트 실행/의미 정확성은 판정하지 않는다.
  빈 registry 설치는 유효하나 검증된 제품 요구사항은 0개다.
- KIT-08: package는 명시적 배포 목록으로 ZIP을 만든다. 로컬 notes/docs/runtime/비밀과
  심볼릭 링크는 혼입하지 않는다. POSIX/PowerShell은 동일 Python packager를 호출한다.
- KIT-09: README, 설치/업그레이드 안내, 버전/로드맵, 템플릿을 동기화한다.
  root에 v1.2 설치한 프로젝트는 legacy 경로를 보존하고 namespaced 방식으로 선택 이관한다.
- KIT-10: ZIP에서 새 프로젝트/재실행/수정 충돌/legacy 보존을 검증하고 AOCortexAPI에서
  server+ios 활성, android 계획을 표시한다. 기존 로그인은 미해결 ISS로 남긴다.

## 인터페이스와 소유권

`python3 scripts/aodocs.py install TARGET [--profile server --profile ios] [--apply]`
`python3 scripts/aodocs.py validate TARGET`
`python3 scripts/release_package.py`

installer: `scripts/aodocs_install.py` → `install(source: Path, target: Path, profiles: list[str], apply: bool) -> list[str]`.
실패는 ValueError/OSError로 전달한다. profiles 생략 시 server. 허용 server/ios/android/web.
validator: `scripts/aodocs_validate.py` → `validate(target: Path) -> list[str]` (오류 목록, 빈 값 성공).
공통 payload 목록: `kit-files.json`의 schema_version=1, files=[상대 파일 경로].
installer/packager는 동일 목록을 읽고 절대경로/../symlink/중복을 거부한다.
목록에는 VERSION/README/CONTRIBUTING/MIGRATION/UPGRADE/RELEASE_POLICY/ROADMAP/CHANGELOG/LICENSE/AGENT_AUDIT_PROMPT,
RULES, examples, scripts의 배포 파일과 kit-files.json만 포함한다. tests/docs는 배포하지 않는다.

설치는 동시 실행/외부 쓰기와의 원자적 트랜잭션을 보장하지 않는다. 정상 preflight 충돌은
전체 변경 전에 실패하며, I/O 중단 시 재실행 전에 diff를 점검한다. 강제 덮어쓰기 옵션은 없다.
공통 킷은 제품 정책보다 우선하는 권한이 아니며 AGENTS/CLAUDE를 자동 수정하지 않는다.

## 검증과 변경 관리

tests는 임시 프로젝트만 사용한다. 신규 도구의 실패 테스트를 먼저 확인한다.
Kit 증거와 제품 기능 증거는 분리한다. checksum 검증은 출처 인증이나 시크릿 감사를 대신하지 않는다.
기존 Platform 포크와 서버 런타임은 변경하지 않는다. 개선 원본과 소비자에 각각 커밋/푸시한다.

## 1.3.1 추가 요구사항 — 첫 소비자 발견

KIT-11: 실제 Git core.autocrlf=true add/commit/clone 이후에도 관리 파일 hash가 동일해야 한다.
`.aodocs/.gitattributes`는 `.gitattributes -text` 및 `kit/** -text whitespace=cr-at-eol`
두 줄로 고정한다. 없으면 추가, 다른 내용/링크/비파일이면 설치 전 중단한다. root Git 속성은 무변경.
manifest payload 밖의 설치 보호 파일이며 1.3.1부터 validator가 존재/내용을 검증한다.
1.3.0의 공개 태그/ZIP은 변경하지 않고 patch로 발행한다.
