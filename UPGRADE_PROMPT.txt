[AOAgentDocs 1.3.1 비파괴 업그레이드]

1. 원본 킷 저장소의 remote/버전/변경 이력을 확인한다. 조직 포크에 git pull을 강제하지 않는다.
2. 대상 .aodocs/manifest.json과 project.json을 확인한다. root .aodocs_version은 legacy 표시이므로 건드리지 않는다.
3. python3 scripts/aodocs.py install TARGET
   dry-run에서 변경/충돌을 확인한다. 기존 project.json의 플랫폼 설정은 유지된다.
4. 충돌이 없으면 --apply로 적용한다. 관리 파일의 로컬 편집/삭제나 payload 제거는 중단 사유다.
   --force는 없다. 필요한 사용자 변경은 프로젝트 문서에 보존하고 diff를 검토한 뒤 별도로 해결한다.
5. 같은 명령으로 재실행해 변경이 없는지 확인한다. 같은 버전이라도 무결성 검사를 생략하지 않는다.
6. python3 scripts/aodocs.py validate TARGET
7. 실제 기능 테스트와 변경 이력을 기록한다. 신규 규약에 등록되지 않은 옛 문서를 무조건 이동하지 않는다.

v1.2 root 복사 설치에서 올 때는 .aodocs/kit만 추가한다. legacy 파일은 그대로 유지하며
어느 규칙을 따를지 프로젝트 문서 지도에서 명시한다. manifest는 root 규칙이 갱신됐다는 주장이 아니다.
킷 내부 파일을 소스로 사용해 같은 프로젝트에 재설치하지 않는다. 별도 다운로드/clone에서 실행한다.
패키지 교체와 project metadata 변경은 분리한다. 토큰/로그/민감정보를 migration 산출물에 포함하지 않는다.

1.3.0→1.3.1은 namespaced .gitattributes를 추가한다. 최종 validate 외에 Git에 등록한 바이트도 보존한다.
이 속성 파일도 사용자 편집과 충돌하면 중단한다. root .gitattributes는 변경하지 않는다.

예외는 이미 Git 줄바꿈 변환을 겪은 정확히 1.3.0 설치본을 1.3.1 이상으로 올릴 때뿐이다.
LF/CRLF 변환만으로 기존 manifest의 SHA-256과 정확히 일치하는 파일은 `repair line endings`로
명시하고 복구한다. 실제 내용 수정, 다른 설치 버전, 동일 1.3.0 재설치는 여전히 충돌이다.
